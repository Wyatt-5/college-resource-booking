## 1. 通用约定
### 1.1 基础

| 项 | 约定 | 与现有代码的一致性 |
|---|---|---|
| Base path | `/api/v1` | `LocationController`、`ItemController` 均为 `/api/v1/...` |
| 传输 | JSON，`Content-Type: application/json`；仅归还提交用 `multipart/form-data` | `ItemImageController` 用 multipart |
| 时间 | ISO-8601 带偏移，服务端存 `TIMESTAMPTZ`，出参统一 `2026-11-03T01:00:00Z` | `V1` 迁移用 `TIMESTAMPTZ` |
| 区间语义 | **左闭右开** `[startAt, endAt)` | 与状态图 `'[)'`、`tstzrange` 一致 |
| 字段命名 | 出参 camelCase；数据库 snake_case | `Item` record 用 camelCase |
| 未知字段 | **拒绝**，返回 `400 VALIDATION_ERROR`，`details` 指出字段名 | `ItemInput.parse` 用白名单校验，同款做法 |

### 1.2 响应信封与分页

```java
public record PageResult<T>(List<T> content, int page, int size, long totalElements) {}
```

| 场景 | 响应 |
|---|---|
| 带 `page` / `size` 参数 | `PageResult<T>`，并附响应头 `X-Total-Count: <totalElements>` |
| 不带分页参数（列表很短） | **裸数组** `T[]`，仍带 `X-Total-Count` |
| 分页参数非法（`page<0`、`size<1`、`size>100`） | `400 VALIDATION_ERROR`，`details.page` / `details.size` |

参数默认值：`page=0`、`size=20`、上限 `size<=100`。

### 1.3 幂等

写操作（`POST` 全部）**必须**带 `Idempotency-Key`，规则与 `catalog.CatalogOperations.once` 一致：

| 检查 | 行为 |
|---|---|
| 未带 / 空白 / 超过 200 字符 | `400 VALIDATION_ERROR`，`details.Idempotency-Key` |
| key 已存在且 `payload_hash` 相同 | 返回**首次结果**（同状态码、同响应体），不重复执行 |
| key 已存在但 `payload_hash` 不同 | `409 IDEMPOTENCY_CONFLICT` |
| `GET` | 不需要 |

```sql
CREATE TABLE reservation_idempotency (
    actor       VARCHAR(200) NOT NULL,
    action      VARCHAR(100) NOT NULL,   -- CREATE / DECIDE:<id> / CANCEL:<id> / PICKUP:<id> / OVERRIDE:<id> / SUBMIT_RETURN:<id>
    request_key VARCHAR(200) NOT NULL,
    payload_hash VARCHAR(64) NOT NULL,
    resource_id BIGINT      NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (actor, action, request_key)
);
```


## 3. 数据模型

### 3.1 预约主对象

```java
public record ReservationSummary(
    long id,
    String resourceType,        // ROOM | ITEM
    Long roomId,                // resourceType=ROOM 时非空
    Long itemId,                // resourceType=ITEM 时非空
    int quantity,               // 会议室恒为 1
    Instant startAt, Instant endAt,
    String status,              // 7 值主状态，见状态图
    String handoverStatus,      // 5 值交接状态；会议室为 null 或 COMPLETED
    String applicantId, String applicantName,
    String purpose,
    int priorityTier,           // 0=COUNSELOR_ADMIN，1=其他；提交时冻结
    long submissionSeq,         // 同资源同时段的排队序
    boolean overdue,            // 派生字段，不落库
    Instant createdAt) {}
```

三个**必须固定**的设计点：

1. **`status` 与 `handoverStatus` 两列分开**，理由见状态图第 1 节。对外两个字段，不要合成一个枚举。
2. **`overdue` 是派生值**：`now() > endAt AND handoverStatus IS DISTINCT FROM 'COMPLETED'`。不加 `OVERDUE` 状态，避免状态机多一个分支。
3. **`priorityTier` 在提交时冻结**：`COUNSELOR_ADMIN` → 0，其余 → 1。不在审批时实时读角色，否则学院后台调一次授权，已排队申请的顺序会漂移（状态图 I4）。

详情比列表多两块：

```java
public record ReservationDetail(
    ReservationSummary summary,
    ApprovalInfo approval,      // 未审批时为 null
    HandoverInfo handover,      // 会议室为 null
    List<ReturnPhoto> photos) {} // 仅归还相关时有值

public record ApprovalInfo(long approverId, String approverName,
                           String decision, String reason, Instant decidedAt) {}
public record HandoverInfo(List<Long> unitIds, String unitCode,
                           Instant pickedUpAt, Instant returnedAt) {}
```

### 3.2 其他对象

| 对象 | 字段 | 说明 |
|---|---|---|
| `Room` | `id, locationId, name, capacity, openFrom, openTo, status, note` | `status: ACTIVE \| INACTIVE` |
| `CalendarDay` | `date, slots: [{startAt, endAt, state}]` | `state: FREE \| OCCUPIED \| BLACKOUT`；**不含申请人、不含事由** |
| `Blackout` | `id, roomId, startAt, endAt, reason` | `reason` 必填 |
| `ApprovalQueueItem` | `id, resourceType, resourceName, applicantName, startAt, endAt, purpose, priorityTier, submissionSeq, waitingSince` | 按 `priorityTier ASC, submissionSeq ASC` 排序 |
| `ReturnPhoto` | `id, storageKey, uploadedAt` | 由 booking 存 `return_photos`，不写 `item_images` |
| `DecisionInput` | `decision: APPROVE \| REJECT`, `reason` | `REJECT` 时 `reason` 必填 |
| `OverrideInput` | `action: CANCEL \| RESCHEDULE`, `reason`, `replacementSlot?` | P1 只实现 `CANCEL` |

## 4. 逐接口定义

### 4.1 `POST /reservations` —— 创建预约（T1 / T2 / T3）

| 项 | 内容 |
|---|---|
| 权限 | `USER` 及以上；只能为自己创建（`applicantId` 取自会话，**不接受请求体传入**） |
| 幂等 | 必须带 `Idempotency-Key` |
| 请求 | `{resourceType, resourceId, startAt, endAt, purpose, quantity?, acceptWaitlist?}` |
| 校验 | `resourceType ∈ {ROOM, ITEM}`；`endAt > startAt`；`startAt ≥ now()-60s`；`quantity ≥ 1`（仅 ITEM）；`purpose` ≤ 200 字 |
| 成功 | `201 Created` + `Location: /api/v1/reservations/{id}`；体：`{id, status, handoverStatus, submissionSeq, priorityTier}` |
| 失败 | `400 VALIDATION_ERROR`（字段级）、`403 FORBIDDEN`（地点超范围）、`404 NOT_FOUND`（资源不存在/停用）、`409 RESOURCE_CONFLICT`（时段被占/容量不足且未接受候补）、`409 INVALID_STATE`（资源 `INACTIVE`） |

**状态判定（按此顺序，不能颠倒）**：

| 条件 | 落库状态 | 迁移 |
|---|---|---|
| 物品 `is_valuable = false` 且容量足够 | `CONFIRMED` + `handoverStatus=NOT_PICKED_UP` | T1 → H1 |
| 贵重物品 或 会议室 | `PENDING_APPROVAL` | T2 |
| 容量不足且 `acceptWaitlist=true` | `WAITLISTED` | T3 |
| 容量不足且未接受候补 | 不落库，`409 RESOURCE_CONFLICT` | — |

会议室走 `PENDING_APPROVAL` 是硬规则：`开发约束.md` 5.3 要求会议室申请由管理员审批。**不要**因为"会议室不贵重"就自动确认。


### 4.2 `GET /reservations/{id}` —— 详情

| 项 | 内容 |
|---|---|
| 权限 | 申请人本人；或 `manages(locationId)` 的管理员 |
| 响应 | `ReservationDetail` |
| 失败 | `404 NOT_FOUND`（**越权也返回 404，不返回 403**，避免用存在性探测他人数据） |

### 4.3 `GET /me/reservations` —— 我的预约

| 项 | 内容 |
|---|---|
| 参数 | `status?`、`handoverStatus?`、`from?`、`to?`、`page`、`size` |
| 响应 | `PageResult<ReservationSummary>`，`ORDER BY startAt DESC` |
| 备注 | 只返回 `applicantId = 当前用户`，**忽略任何客户端传入的 `applicantId`** |

### 4.4 `GET /reservations` —— 管理端筛选

| 项 | 内容 |
|---|---|
| 权限 | `RESOURCE_MANAGER` 及以上；普通用户 `403 FORBIDDEN` |
| 参数 | `resourceType?`、`resourceId?`、`status?`、`handoverStatus?`、`applicantId?`、`locationId?`、`from?`、`to?`、`page`、`size` |
| 响应 | `PageResult<ReservationSummary>` |
| 越权处理 | **授权范围必须进 SQL 的 `WHERE`**（`location_id IN (...)`），不能查完再内存过滤 —— 否则分页会错位、`X-Total-Count` 会泄露总数（测试用例 12 断言这一点） |

### 4.5 `POST /reservations/{id}/cancel` —— 取消（T7 / T9 / T10）

| 项 | 内容 |
|---|---|
| 权限 | 申请人本人；或管理员（需 `reason`，写入审计） |
| 请求 | `{reason?}` |
| 允许的起始状态 | `PENDING_APPROVAL`、`WAITLISTED`、`CONFIRMED` 且 `handoverStatus` 为 `null`/`NOT_PICKED_UP` |
| 成功 | `200`，体：`{id, status:"CANCELLED", waitlistPromoted?: <新预约 id>}` |
| 失败 | `409 INVALID_STATE`（已取件/已提交归还不能取消）、`403 FORBIDDEN`（非本人且无管理权限） |

**必须同事务完成**：置 `CANCELLED` → 按 `priorityTier ASC, submissionSeq ASC` 找到最早候补 → 置 `CONFIRMED` → 写审计 → 写通知。**不要**等 worker。返回值里的 `waitlistPromoted` 让前端能提示"已为候补同学让出名额"。

### 4.6 `GET /approval-queue` —— 审核工作台

| 项 | 内容 |
|---|---|
| 权限 | `RESOURCE_MANAGER`、`COUNSELOR_ADMIN`（`SYSTEM_ADMIN` 亦可）；普通用户 `403 FORBIDDEN` |
| 参数 | `resourceType?`、`locationId?`、`page`、`size` |
| 响应 | `PageResult<ApprovalQueueItem>`，排序 `priorityTier ASC, submissionSeq ASC` |
| 过滤 | 排除 `applicantId = 当前用户` 的条目（**从源头就不给自审入口**，比事后拦更稳） |
| 越权 | 只返回 `manages(locationId)` 范围内的 |

### 4.7 `POST /reservations/{id}/decision` —— 单人审批（T4 / T5）

| 项 | 内容 |
|---|---|
| 权限 | `RESOURCE_MANAGER`、`COUNSELOR_ADMIN`，且 `approverId ≠ applicantId` |
| 幂等 | 必须带 `Idempotency-Key`（两名审核员连点，靠这个 + 条件更新双保险） |
| 请求 | `{decision: "APPROVE" | "REJECT", reason}` |
| 成功 | `200`，体：`{id, status, decidedAt}` |
| 失败 | `403 SELF_APPROVAL_FORBIDDEN`（自审，预约**保持** `PENDING_APPROVAL`）、`409 INVALID_STATE`（已被他人处理）、`409 RESOURCE_CONFLICT`（通过时容量已被占满，**状态保持 `PENDING_APPROVAL`，不自动转候补**）、`400 VALIDATION_ERROR`（`REJECT` 未填 `reason`） |

**并发写法**：用条件更新的影响行数判断，禁止先 `SELECT` 再 `UPDATE`：

```sql
UPDATE reservations SET status = 'CONFIRMED', ...
 WHERE id = ? AND status = 'PENDING_APPROVAL';
-- 影响 0 行 → 409 INVALID_STATE
```

### 4.8 `POST /reservations/{id}/pickup` —— 确认取件（H2）

| 项 | 内容 |
|---|---|
| 权限 | 申请人本人 |
| 请求 | `{unitIds: [12, 13]}`（会议室无此端点） |
| 成功 | `200`，体：`{id, handoverStatus:"CHECKED_OUT", unitCodes:[...]}` |
| 失败 | `409 INVALID_STATE`（非 `NOT_PICKED_UP`）、`409 RESOURCE_CONFLICT`（`unitId` 不属该物品或已被占）、`403 FORBIDDEN`（非本人） |

**同事务双写**：`reservations.handover_status = 'CHECKED_OUT'` 且 `item_units.status = 'CHECKED_OUT'`（写入方约定见 7.2）。

### 4.9 `POST /reservations/{id}/return-submission` —— 提交归还（H3 / H6）

| 项 | 内容 |
|---|---|
| 权限 | 申请人本人 |
| 请求 | `multipart/form-data`：`photos`（≥1 张，jpg/png/webp）、`remark?` |
| 成功 | `200`，体：`{id, handoverStatus:"RETURN_SUBMITTED", photoCount}` |
| 失败 | `400 VALIDATION_ERROR`（无文件/类型不符）、`413`（超限）、`409 INVALID_STATE`（非 `CHECKED_OUT` 或 `RETURN_REJECTED`） |

允许从 `RETURN_REJECTED` 重新提交（H6），此时旧照片保留、追加新照片。

### 4.10 `POST /reservations/{id}/return-verification` —— 归还核验（H4 / H5）

| 项 | 内容 |
|---|---|
| 权限 | `RESOURCE_MANAGER` 且 `manages(locationId)` |
| 请求 | `{decision: "ACCEPT" | "REJECT", reason}` |
| 成功 | `200`，体：`{id, handoverStatus:"COMPLETED"}` 或 `{id, handoverStatus:"RETURN_REJECTED"}` |
| 失败 | `409 INVALID_STATE`（非 `RETURN_SUBMITTED`、缺照片、实物未进入待核验）、`400`（`REJECT` 未填原因） |

**语义已由 catalog 固定**（`ReturnVerificationService`）：`ACCEPT` → `COMPLETED`，`REJECT` → `RETURN_REJECTED`；这两种值会通过 `ReservationReturnGateway.finish()` 传给我方。见 7 节。

### 4.11 `POST /reservations/{id}/override` —— 辅导员强制占用（T11）

| 项 | 内容 |
|---|---|
| 权限 | `COUNSELOR_ADMIN` |
| 请求 | `{action: "CANCEL", reason, replacementSlot?}` |
| 成功 | `200`，体：`{id, newReservationId, overriddenReservationId}` |
| 失败 | `403 OVERRIDE_NOT_ALLOWED`（角色不符或非会议室）、`409 INVALID_STATE`（目标非 `CONFIRMED`）、`400`（`reason` 为空） |

**必须同事务完成**：新建辅导员那条 `CONFIRMED` → 原预约置 `OVERRIDDEN`（**不占名额**）→ 写审计 → 写通知（通知受影响用户）。`replacementSlot` P1 不收，传了就 `400`。

### 4.12 会议室四个端点

| 端点 | 关键点 |
|---|---|
| `GET /rooms` | 支持 `locationId?`、`status?`、`page/size`；普通用户只看 `ACTIVE` |
| `GET /rooms/{roomId}` | 返回 `openFrom`/`openTo` |
| `POST /rooms` / `PATCH /rooms/{roomId}` | `RESOURCE_MANAGER` 且 `manages(locationId)`；`capacity` 固定 1，**不接受传入**；初始只有两间，新增须写明原因（写审计） |
| `GET /rooms/{roomId}/calendar?from&to` | 见下 |

**日历脱敏（验收条件 #16）**：只返回时段与状态，**不返回申请人姓名、事由、预约 id**：

```json
{ "roomId": 3, "from": "2026-11-03", "to": "2026-11-09",
  "days": [ { "date": "2026-11-03",
              "slots": [ { "startAt": "2026-11-03T01:00:00Z", "endAt": "2026-11-03T02:00:00Z", "state": "OCCUPIED" } ] } ] }
```

`from`/`to` 跨度上限 31 天，超出 `400 VALIDATION_ERROR`。

## 5. 错误码总表

| HTTP | code | 触发场景 | 前端应对 |
|---|---|---|---|
| 400 | `VALIDATION_ERROR` | 字段非法/缺失/未知字段/分页参数错 | 按 `details` 的字段名高亮 |
| 401 | `UNAUTHENTICATED` | 未登录或 token 失效 | 跳登录 |
| 403 | `FORBIDDEN` | 角色不足、超出地点范围 | 提示无权 |
| 403 | `SELF_APPROVAL_FORBIDDEN` | 审批自己的申请 | 提示"不能审批自己的申请" |
| 403 | `OVERRIDE_NOT_ALLOWED` | 非辅导员或非会议室 | 隐藏入口 |
| 404 | `NOT_FOUND` | 不存在**或越权不可见** | 提示刷新 |
| 409 | `INVALID_STATE` | 当前状态不允许此动作/已被他人处理 | **刷新详情**，不要重试 |
| 409 | `RESOURCE_CONFLICT` | 时段被占、容量不足、实物被占 | 提示换时段或进候补，可用 `details.conflicts` 高亮 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一 key 用于不同内容 | 前端 bug，换 key |
| 413 | `VALIDATION_ERROR` | 上传超限 | 压缩重传 |
| 503 | `DATABASE_UNAVAILABLE` | 数据库不可用 | 稍后重试 |
| 503 | `DEPENDENCY_UNAVAILABLE` | 依赖模块未接入 | 提示功能未就绪 |

**`INVALID_STATE` 与 `RESOURCE_CONFLICT` 不能混用**：前者是"这个状态下不能干这事"（刷新即可），后者是"资源被别人抢了"（要换时间）。前端给出完全不同的提示，混用会让用户以为系统坏了。

## 6. 接口 → 状态迁移对照

这是评审时最容易被问的一张表：**每个写接口必须对应状态图里已定义的迁移**，没有例外。

| 接口 | 迁移 | 允许的起始状态 | 落库结果 |
|---|---|---|---|
| `POST /reservations` | T1 / T2 / T3 | — | `CONFIRMED`(+H1) / `PENDING_APPROVAL` / `WAITLISTED` |
| `POST /{id}/cancel` | T7 / T9 / T10 | `PENDING_APPROVAL` / `WAITLISTED` / `CONFIRMED`(未取件) | `CANCELLED` |
| `POST /{id}/decision` `APPROVE` | T4 | `PENDING_APPROVAL` | `CONFIRMED`(+H1) |
| `POST /{id}/decision` `REJECT` | T5 | `PENDING_APPROVAL` | `REJECTED` |
| `POST /{id}/pickup` | H2 | `NOT_PICKED_UP` | `CHECKED_OUT` |
| `POST /{id}/return-submission` | H3 / H6 | `CHECKED_OUT` / `RETURN_REJECTED` | `RETURN_SUBMITTED` |
| `POST /{id}/return-verification` `ACCEPT` | H4 | `RETURN_SUBMITTED` | `COMPLETED`（释放名额） |
| `POST /{id}/return-verification` `REJECT` | H5 | `RETURN_SUBMITTED` | `RETURN_REJECTED` |
| `POST /{id}/override` | T11 | `CONFIRMED`（会议室） | 原预约 `OVERRIDDEN` + 新预约 `CONFIRMED` |
| 定时任务 / 查询时判定 | T6 / T8 / T12 / H7 | 见状态图 | `EXPIRED` / 候补转正 / 会议室 `COMPLETED` |

`T6`、`T8`、`T12`、`H7` **没有对应的 HTTP 端点**，这是有意的：它们由定时任务或查询时惰性判定触发，暴露成接口会被前端误用。`T8`（候补转正）在 `cancel` 的**同一事务内**完成，不单独开接口。
