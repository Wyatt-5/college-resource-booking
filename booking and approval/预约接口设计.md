# 预约接口与调用说明

更新于 2026-11-15，对应 develop 的 c8142d7 功能版本。本文列出当前已实现的预约、地点、交接和任务接口，替代早期规划中的 rooms、候补和优先占用接口。完整字段见 [OpenAPI](../contracts/openapi/openapi.yaml)，状态含义见 [状态说明](预约状态图.md)。

## 通用约定

- 所有路径以 `/api/v1` 开头。资源类型为 `ITEM` 或 `SPACE`。
- 时间使用带时区的ISO 8601字符串，数据库保存 `TIMESTAMPTZ`；页面按北京时间展示。区间为 `[startAt, endAt)`。
- 浏览器先调用 `GET /auth/csrf`，保留会话Cookie，写请求携带返回的CSRF请求头；登录与退出也遵守此约定。内部任务接口单独使用服务令牌，不接受用户会话代替。
- 预约列表、待审队列、日志和提醒返回 `{content,page,size,totalElements}`；默认页码0、每页20，最多100。不要假定所有列表均返回数组或都带 `X-Total-Count`。
- 地点列表、地点时段及归还核验队列使用各自定义的数组响应，不能套用统一分页假设。
- 非成功响应使用 `{code,message,details,requestId}`，错误码和状态码应按实际接口处理。

## 身份与权限

普通用户管理自己的预约与交接。审核员和系统管理员可审核他人申请、维护资源、核验归还、查看全量预约日志和未归还提醒。只有系统管理员创建、停用其他账号和调整身份；任何管理身份均不能审核自己的申请。

旧 `COUNSELOR_ADMIN`、`RESOURCE_MANAGER` 仅作为兼容授权，当前不提供辅导员优先占用或按地点限制管理权限的流程。详见 [账号与权限](../docs/账号与权限矩阵.md)。

## 预约与查询

| 方法与路径 | 用途 | 身份与关键限制 |
| --- | --- | --- |
| POST /reservations | 提交物品或地点预约 | 已登录，必须带预约防重复键 |
| GET /me/reservations | 本人预约分页 | 仅本人 |
| DELETE /me/reservations/{reservationId} | 取消本人预约 | 尚未开始，待审或已确认，且尚未领取 |
| GET /review/reservations | 待审队列分页 | 审核员或系统管理员；只列尚未到开始时间的待审申请 |
| PATCH /reservations/{reservationId}/review | 批准或拒绝 | 审核员或系统管理员，申请人不能自审 |
| GET /management/reservations | 预约日志分页 | 审核员或系统管理员，可选itemId、status、keyword |
| GET /items/{itemId}/availability?date=YYYY-MM-DD | 物品该日时段余量与待审数量 | 公开上架物品可查询 |

创建请求示意如下。资源ID和时间须替换为环境中有效且符合预约规则的值：

```json
{
  "resourceType": "ITEM",
  "resourceId": 1,
  "startAt": "2026-11-16T10:00:00+08:00",
  "endAt": "2026-11-16T12:00:00+08:00",
  "purpose": "学院活动",
  "quantity": 1
}
```

物品允许跨天整点预约，需满足物品的提前天数、最长借用天数和容量限制。普通物品成功后为 `CONFIRMED`，贵重物品为 `PENDING_APPROVAL`。地点使用 `resourceType=SPACE`，数量为1，只允许未来一周内同一天08:00至22:00的整点时段，成功后均待审。

审核请求为 `{"decision":"APPROVE"}` 或 `{"decision":"REJECT","reason":"原因"}`。拒绝原因必填，最多300字；批准时复核当前时段容量，已到开始时间的申请不能批准。审核日志返回审核人、结论、理由和时间；系统自动过期显示 `decision=EXPIRED`。

2026-11-16整合版本新增日志status与keyword筛选：status只能是五种预约主状态，keyword最多50字符，匹配申请人姓名、账号及资源名，不区分大小写，百分号、下划线和反斜线按字面匹配。省略条件沿用原列表行为；计数和分页使用同样条件。此能力随PR16与PR17整合更新交付，具体版本以develop提交记录为准。

创建接口的响应包含预约数据及 `Location`，但当前没有单独的 `GET /reservations/{id}` 路由；不能把该响应头当成详情读取接口已实现的依据。页面详情使用已取得的本人预约记录。

## 可预约地点

| 方法与路径 | 用途 |
| --- | --- |
| GET /spaces | 公开读取启用地点数组 |
| POST /spaces | 管理员新增地点 |
| PATCH /spaces/{id} | 管理员编辑地点 |
| DELETE /spaces/{id} | 管理员停用地点，保留历史并检查未结束预约 |
| GET /spaces/{id}/slots?date=YYYY-MM-DD | 公开读取已占用或待审整点时段数组，不返回申请人资料 |
| POST /spaces/{id}/image | 管理员上传或替换照片，multipart字段为file |
| GET /spaces/{id}/image | 公开读取照片 |

存放地点使用独立的 `/locations`，不是可预约地点。当前没有 `/rooms`、blackouts、候补或override路由。

## 领取归还和核验

| 方法与路径 | 输入或响应 | 身份与防重复要求 |
| --- | --- | --- |
| POST /reservations/{reservationId}/pickup | JSON：unitCodes数组 | 本人；使用时段内；Idempotency-Key |
| POST /reservations/{reservationId}/return-submission | multipart：photos与可选remark | 本人；Idempotency-Key |
| GET /reservations?handoverStatus=RETURN_SUBMITTED | 当前待核验归还数组 | 审核员或系统管理员 |
| POST /reservations/{reservationId}/return-verification | JSON：decision为ACCEPT或REJECT，拒绝需reason | 审核员或系统管理员；Idempotency-Key |
| GET /return-photos/{photoId} | 受保护的归还照片 | 本人或有管理权限者 |

领取的 `unitCodes` 为实物编号字符串数组，不是实物ID；数量须与预约数量一致，不重复，且均属于当前物品和可借状态。归还需1至6张JPG、PNG或WebP，单张最大5MiB，备注最多300字。

交接响应包含 `id`、`handoverStatus`、`unitCodes` 数组、`photoCount` 和 `lastReturnReason`。不能把提醒接口中用顿号分隔的 `unitCodes` 字符串当成交接数组使用。核验接受后恢复实物可借，驳回后仍占用且允许重提。

## 幂等与重试

| 操作 | 当前机制 |
| --- | --- |
| 创建物品或地点预约 | Idempotency-Key为8至100位字母、数字或点、下划线、冒号、连字符；按申请人与键去重，内容不同返回409 IDEMPOTENCY_CONFLICT |
| 领取、提交归还和归还核验 | 必填Idempotency-Key，非空且最长200字符；按操作身份、动作、键与内容校验，重复请求不重复产生副作用 |
| 审核与取消 | 不要求Idempotency-Key，依靠身份与条件更新检查；重复处理通常返回409 INVALID_STATE |
| 内部任务完成或失败报告 | 任务ID与leaseToken校验，不使用浏览器的防重复键 |

网络重试应沿用原请求键与原内容。幂等保证不重复执行，并不承诺永远返回第一次的历史响应快照。不要把所有POST一概视为需要同一种防重复键。

## 自动过期与未归还提醒

`GET /return-reminders?managed=false&page=0&size=20` 返回本人当前提醒；`managed=true` 仅审核员和系统管理员可查看全部。字段包含预约ID、物品名、申请人ID和姓名、应归还时间、交接状态、实物编号字符串、提醒内容和生成时间。

后台已实现 `POST /internal/tasks/claim`、`POST /internal/tasks/{id}/complete` 和 `POST /internal/tasks/{id}/fail`。这些接口只供独立worker使用 `TASK_SERVICE_TOKEN` 调用；密钥至少32字符，不能放前端或提交Git。默认30秒扫描，180秒租约，最多5次尝试。

待审申请到开始时间仍未获批时过期并记录系统结果；已领取且到结束时间仍未完成归还的物品生成提醒。已提交核验时暂不展示提醒，驳回后重新展示，核验接受后不再展示。提醒不能恢复库存，未领取预约也不会被任务自动取消。详细故障恢复见 [独立任务服务说明](../docs/独立任务服务接口草案.md)。

## 常见失败

| HTTP状态与错误码 | 含义 |
| --- | --- |
| 400 VALIDATION_ERROR | 时间、数量、用途、分页、请求键或其他输入无效 |
| 401 UNAUTHENTICATED或SESSION_EXPIRED | 未登录或会话失效 |
| 403 FORBIDDEN | 无权限，或浏览器写操作缺少有效CSRF |
| 409 SELF_APPROVAL_FORBIDDEN | 审核自己的申请 |
| 409 RESERVATION_EXPIRED | 申请已开始，不能再批准 |
| 409 INVALID_STATE | 当前状态不允许此操作或已被处理 |
| 409 RESOURCE_CONFLICT | 时段容量不足或实物不可用 |
| 409 IDEMPOTENCY_CONFLICT | 原键被用于不同请求内容 |
| 401 INVALID_SERVICE_TOKEN | 内部任务服务令牌缺失或无效 |
| 409 LEASE_EXPIRED | 内部任务租约过期或不匹配 |

其他上传、资源停用、未找到或依赖失败错误以对应接口契约为准，不承诺返回旧设计里的conflicts数组或候补建议。
