# 前端开发说明

Vue 3 + Vite。用户端和管理端共用网站、登录会话和后端；页面根据账号权限显示不同入口，后端负责最终权限判断。普通用户从“我的”查看预约、反馈和资料；管理端包含库存、地点、归还核验、账号、审核、公告和反馈。

## 本地启动

先按根目录 README 启动 PostgreSQL 和后端，确认 `http://127.0.0.1:8080/api/v1/health` 返回正常。再在项目根目录执行：

```powershell
cd frontend
npm ci
npm run dev
```

打开 Vite 输出的地址。开发服务器将 `/api` 代理到本机 8080；要临时调整目标，在启动 Vite 的同一终端设置 `API_PROXY_TARGET`。前端不直接连接数据库，也不保存真实密码。

```powershell
npm test
npm run build
```

## 当前功能和注意事项

- 物品、地点、预约、领取、归还、审核、日志、公告、反馈及账号资料均有真实接口；请求失败应显示错误，不能当成成功。
- 账号分普通用户、审核员、系统管理员。系统管理员创建账号、分配其他人的权限；账号和姓名本人不能修改。普通用户也可在“我的”维护联系资料和头像。
- 存放地点与可预约地点分开维护；物品预约可跨天，地点预约按开放时间和整点提交。具体限制由后端校验。
- 用户端和管理端支持已打开页面标签；切换可保留页面状态，关闭标签后重新进入会重建，刷新整个网页会重置标签。
- 布局包含响应式样式，但后续改动需重新检查 320/390 等窄屏和真实手机，尤其拍照、登录及弹窗。
- `VITE_ENABLE_MANAGEMENT_DEMO=true` 只用于本地开发演示；不要以演示数据代替联调或验收。日常调试使用真实后端。

主要代码：`src/App.vue` 负责导航与登录态；`src/features/` 和 `src/components/` 为页面；`src/lib/api.js` 为 API；`src/styles.css` 为共享样式。页面改动涉及接口时同步检查 `../contracts/openapi/openapi.yaml`。
