# scripts

## e2e-预约冲突与日志.sh

预约冲突、审批、日志模块的多账号端到端校验，共 10 组 25 项检查。它直接打真实后端接口（不走浏览器），用来证明「学生与辅导员同段提交 → 审核人决定 → 防双订 → 并发只成一次 → 日志含审核人与结论」这条链路成立。

### 前提

1. 后端已在 `127.0.0.1:8080` 运行，且连的是**有演示数据**的库（`student01` / `counselor01` / `reviewer01` / `admin` 四个账号存在）。
2. 待审队列里不要有大量并存申请，否则「挑空闲时段」会一直撞车。
3. 脚本会往库里写入**明天整点**的预约记录（用途字段以「冲突校验-」「并发同单」开头），跑完可手动取消，或换一个日期再跑。

### 配置密码

仓库不保存任何账号密码。在**仓库根目录**的 `.env` 里加四行（该文件已被 git 忽略）：

```
E2E_STUDENT_PASS=学生账号密码
E2E_COUNSELOR_PASS=辅导员账号密码
E2E_REVIEWER_PASS=审核员账号密码
E2E_ADMIN_PASS=管理员账号密码
```

账号名默认 `student01` / `counselor01` / `reviewer01` / `admin`，如需改动直接改脚本第 1 节。后端地址可用 `E2E_BASE` 覆盖，默认 `http://127.0.0.1:8080/api/v1`。

### 运行

```bash
bash scripts/e2e-预约冲突与日志.sh
```

全部通过时最后一行是 `== 结果：通过 25 项，失败 0 项 ==`，退出码为 0；有失败则退出码为 1，便于挂到 CI 或手势脚本里。

### 覆盖的检查项

| 组 | 检查内容 |
| --- | --- |
| 1 | 四个账号登录均返回 200 |
| 2 | 学生提交明天某个整点时段成功 |
| 3 | 辅导员提交同一时段也成功，状态为待审核 |
| 4 | 待审队列可读；两人 `priorityTier` 均为 `STANDARD`（主线定稿：队列按提交顺序，不按身份区分） |
| 5 | 学生审核自己的申请 → 409 `SELF_APPROVAL_FORBIDDEN` |
| 6 | 审核人可批准学生，状态变 `CONFIRMED` |
| 7 | 再批准同一时段的辅导员申请 → 409 `RESOURCE_CONFLICT`（防双订） |
| 8 | 重复审核同一单 → 409 `INVALID_STATE` |
| 9 | 日志按状态+关键字筛选、含 `reviewerName` 与 `decision`、非法状态 400、学生访问 403 |
| 10 | 两名审核员并发批准同一单：一次 200、一次 409 |
