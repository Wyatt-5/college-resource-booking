# 资源、预约和现有接口

更新于 2026-11-08，依据本地 `integration-week2` 工作区代码。GitHub `develop` 可能尚未包含整合分支的修改；请以实际拉取的版本为准。接口字段详见 `contracts/openapi/openapi.yaml`，调用前还应核对 Controller 和测试。

## 三种资源

| 资源 | 用途 | 代码 |
| --- | --- | --- |
| 存放地点 | 办公室、物资室，物品属于其中一个地点，本身不能预约 | `location/`；`locations` |
| 物品及实物 | 物品包含名称、规则、照片和贵重标记；每件实物有自动生成的编号 | `catalog/`；`items`、`item_units` |
| 可预约地点 | 会议室或其他活动地点，和存放地点分别管理 | `booking/SpaceController`；`bookable_spaces` |

## 已实现的主要入口

以下路径以 `/api/v1` 开头；写操作使用会话和 CSRF，具体权限和错误以服务端为准。

| 功能 | 主要接口 | 说明 |
| --- | --- | --- |
| 登录和账号 | `/auth/csrf`、`/auth/login`、`/auth/me`、`/auth/logout`；`GET/POST /users`、`DELETE /users/{id}`、`PUT /users/{id}/grants` | 系统管理员创建、停用和分配其他账号权限。停用账号可用原账号名及姓名重新启用，保留历史、重设密码并清除旧权限 |
| 个人资料 | `GET/PATCH /users/me/details`、`POST /users/me/avatar`、`GET /users/{id}/avatar`、`GET/POST /departments` | 用户管理自己的部门、邮箱、手机和头像；仅系统管理员新增部门 |
| 存放地点 | `GET /locations`、`PATCH/DELETE /locations/{id}`、`GET/POST /locations/{id}/image` | 编辑、照片和停用；仍有物品或未完成借还时禁止移除 |
| 物品及照片 | `GET/POST /items`、`GET/PATCH/DELETE /items/{id}`、`GET /items/{id}/units`、`PUT /items/{id}/stock`、`GET/POST /items/{id}/images`、`GET/DELETE /items/{id}/images/{imageId}` | 已有浏览、上架、编辑、库存、图片和停用，具体限制由后端校验 |
| 可预约地点 | `GET/POST /spaces`、`PATCH/DELETE /spaces/{id}`、`GET /spaces/{id}/slots`、`GET/POST /spaces/{id}/image` | 管理员维护地点及图片，用户查询按天的时段 |
| 预约与审批 | `POST /reservations`、`GET /me/reservations`、`DELETE /me/reservations/{id}`、`GET /review/reservations`、`PATCH /reservations/{id}/review` | 同一入口用 `resourceType` 区分 `ITEM` 和 `SPACE`；申请人不能审核自己 |
| 时段与日志 | `GET /items/{id}/availability?date=...`、`GET /management/reservations` | 时段库存和预约日志；日志包含审核人、结论、时间和理由 |
| 领取归还 | `POST /reservations/{id}/pickup`、`POST /reservations/{id}/return-submission`、`GET /return-photos/{photoId}` | 领取绑定编号；归还上传 1–6 张照片和可选备注；写请求需要幂等键 |
| 管理员核验 | `GET /reservations?handoverStatus=RETURN_SUBMITTED`、`POST /reservations/{id}/return-verification` | 审核照片；通过释放实物，驳回后可重新提交 |
| 公告与反馈 | `GET/POST /announcements`、`PUT /announcements/{id}`、`GET/POST /feedback`、`PUT /feedback/{id}` | 用户看已发布公告、提交和查看本人反馈；有管理权限者管理公告和反馈 |

## 预约规则与验收边界

- 普通物品在时段库存允许时自动确认；贵重物品和可预约地点需他人单人审核。审核人可在冲突申请中选择，批准时后端再次检查容量；不能审核自己的申请。
- 物品预约按整点，可跨天，受该物品提前天数和最长借用天数限制；地点预约限未来一周内、同一天 08:00–22:00 整点时段。请求使用幂等键。
- `unitSummary.available` 是当前实物状态，不等于任意未来时段的可借量；查看时段后仍由后端最终判断。
- 审批状态 `status` 与交接状态 `handoverStatus` 分开；归还审核前不应把实物视为可借。
- 手机真机、多账号端到端、跨机器部署与备份恢复仍需验收。详细历史和测试以[开发日志](开发日志.md)为准。
