| 功能 | 状态 |

## 请求与响应

所有地址以 /api/v1 为前缀。具体字段、示例和错误以 contracts/openapi/openapi.yaml 为准。

- 物品：id、locationId、name、description、isValuable、status、rules、unitSummary、createdAt、images。
- rules：maxBorrowDays（最长借用天数）、advanceDays（最多提前天数，允许0）。
- 未配置规则返回 null，不解释为无限制；前端显示“尚未配置”。
- unitSummary：total、available，由后端计算当前实物状态，不代表指定预约时段可用量。
- 图片元数据：id、itemId、fileName、url；不返回服务器存储键或文件路径。
- 时间为 UTC 的 ISO 8601；显示时使用上海时区。

| 方法与路径 | 用途及约束 |
|---|---|
| GET /items | 不传分页参数时兼容原数组格式，默认最多20条；显式传page或size返回分页对象；X-Total-Count提供总数 |
| GET /items?page=0&size=12 | 分页对象：content、page、size、totalElements |
| GET /items/{itemId} | 公开详情只显示启用地点下ACTIVE物品 |
| GET /items?scope=managed | 仅列出当前身份有管理范围的物品，支持status |
| GET /items/{itemId}?managed=true | 查看本人可管理的物品，包括停用物品 |
| POST /items | 创建，201；Idempotency-Key必填，按身份和请求内容防重复 |
| PATCH /items/{itemId} | 部分更新；rules也按子字段合并；移动地点同时校验新旧地点权限 |
| GET/POST /items/{itemId}/units | 管理员查询/新增编号；新增201，unitCode最多40字符 |
| PATCH /items/{itemId}/units/{unitId} | 维护实物状态，成功200 |
| GET/POST /items/{itemId}/images | 登录后读取图片元数据／管理员上传，字段名file；上传201 |
| GET /items/{itemId}/images/{imageId} | 登录并检查访问范围后读取图片，no-store、nosniff |
| DELETE /items/{itemId}/images/{imageId} | 管理员删除，204 |
| GET /reservations?status=RETURN_SUBMITTED | 返回核验队列，page从0开始；真实预约适配器缺失时503 |
| POST /reservations/{id}/return-verification | decision为ACCEPT/REJECT，驳回必填reason；Idempotency-Key必填 |

名称最多50字符、介绍最多300字符。名称和地点必填。
请求格式错误使用400 VALIDATION_ERROR，details按字段名给出原因。
其他错误包括401 UNAUTHENTICATED、403 FORBIDDEN、404 NOT_FOUND、409 INVALID_STATE或IDEMPOTENCY_CONFLICT、503 DEPENDENCY_UNAVAILABLE或DATABASE_UNAVAILABLE。
错误体带code、message、details、requestId，响应头带X-Request-Id。

## 数据库迁移

V3建立items、item_units、item_images；V4新增按天规则、图片文件名、幂等记录、资源审计待发送事件，调整物品内编号唯一约束和停用枚举。
已执行的V1/V2/V3不修改。合并前需与其他后端协调V3/V4编号。

为保护已有数据，旧max_borrow_hours保留；整天时长回填max_borrow_days，非整天规则不自动向上/向下取整，需要明确复核配置。
旧INACTIVE实物状态迁移为DISABLED。现有名称/介绍不截断，新写入接口执行50/300限制。

catalog_audit_outbox是资源模块的事务事件表，包含操作者、动作、对象、前后状态和时间。
全局审计模块应消费并记录事件，再标记delivered_at；当前没有第二套公共审计查询接口。

## 认证与预约接入边界

ServletCatalogAccess只接受经过认证模块建立的HttpServletRequest.getUserPrincipal()和服务端角色。
不会信任X-Role、前端页面状态或mock-token。

- SYSTEM_ADMIN、COUNSELOR_ADMIN可管理全部地点。
- 范围授权通过CatalogScopeProvider.manageableLocations(principalName)提供。
- 尚无授权服务时，普通身份的管理范围为空，不能放行修改。
- 认证模块需要负责令牌/会话校验和相应CSRF保护。前端目前按PR #2约定发送Bearer令牌。
- 正式登录接口尚未提供；不能使用admin/admin123完成真实管理操作。

预约模块实现ReservationReturnGateway：
1. lock在同一数据库事务内锁定预约，提供真实地点、物品、已绑定实物、归还照片和当前状态。
2. queue在SQL分页前按身份管理范围筛选，只返回待核验记录。
3. finish在同一事务内记录核验人/原因并更新预约状态，不使用跨机器HTTP代替本地事务。
4. 核验服务接受后恢复实物AVAILABLE；驳回保持占用。适配器失败时库存和幂等记录一同回滚。
5. 既有预约的贵重标记/规则快照由预约模块保存，物品编辑不能改写历史申请。

适配器未提供时，核验返回503 DEPENDENCY_UNAVAILABLE，前端默认提示待接入。
auth/users等保留的OpenAPI是协作草案，不能当成已实现接口。

## 清单中暂定规则的当前实现

| 事项 | 本地采用方案 | 需要组内确认 |
|---|---|---|
| 图片张数 | 默认6张，CATALOG_IMAGE_MAX_COUNT可配置 | 张数上限 |
| 图片格式/大小 | JPEG、PNG、WebP，单张最多5MiB；额外限制解码尺寸 | 若有学院特殊要求再调整 |
| 管理维护状态 | AVAILABLE、MAINTENANCE、DISABLED、LOST | 确认与预约状态配合 |
| 系统占用状态 | CHECKED_OUT、RETURN_SUBMITTED，仅交接服务更新 | 预约/交接模块确认 |
| 重复编号 | 同一物品内唯一，重复400，与原前端清单一致 | 如团队统一409需同步调整 |
| 库存口径 | 当前AVAILABLE件数；时段库存另实现 | 与预约模块确认 |
| 物品列表 | 无分页参数兼容数组，带分页参数返回分页对象 | 前端确认兼容方案 |
| 归还队列 | 复用GET /reservations?status=RETURN_SUBMITTED | 预约模块确认适配器 |

以上是可审查的本地方案，未冒充团队已确认的结论。

## 运行和验证

本机.env设置DB_PORT=15432，队友未设置时默认5432；Compose和后端共用配置。
密码不提交。CATALOG_IMAGE_DIRECTORY可设置图片目录，需对数据库和照片一起备份。

在backend目录：
- 普通测试：.\mvnw.cmd test
- 真实数据库测试：先启动数据库，再设置CATALOG_DB_TEST=true后运行.\mvnw.cmd test
- 启动：.\mvnw.cmd spring-boot:run

在frontend目录：
- npm ci
- npm test
- npm run build
- npm run dev

管理操作默认调用真实接口。VITE_ENABLE_MANAGEMENT_DEMO=true仅在开发模式显式启用原前端模拟页面，不会自动降级。
浏览始终使用真实接口。

本地测试覆盖字段契约、参数错误、范围授权、上架并发幂等、部分修改、编号唯一、占用状态保护、照片格式/尺寸/张数、受控读取与删除、核验通过/驳回及失败回滚。
本次最终验证：19项后端测试全部通过（含真实PostgreSQL），9项前端接口测试全部通过，前端生产构建及后端verify打包通过。OpenAPI已解析并校验引用；生产JAR不包含本机测试身份入口。
浏览器使用独立测试身份实际走通上架、合成图片上传、编号录入、维修状态更新、库存页追加编号及用户端受控照片读取；发现并修复上传成功后状态未刷新的问题。测试物品、生成照片已清理，测试入口已关闭，正式后端匿名写入返回401。
正式账号和真实预约适配器接入后的全流程联调仍待完成。

用于浏览器验收的CatalogBrowserHarness位于src/test/java/local/catalog/harness，需显式设置CATALOG_BROWSER_TEST=true，只监听127.0.0.1，不打包进生产JAR。
它只模拟身份，实际目录、图片和数据库均使用真实代码；不代表正式登录已完成。
测试完成后关闭该入口并清理临时记录。
