# 物品模块接口核对清单（4 号 ↔ 3 号）

这份清单用于提交 PR 前，由李舒达（前端）和肖志（后端）逐项口头核对。依据是 `contracts/openapi/openapi.yaml` 和 `docs/开发约束.md` 的 5.2、5.4 两节。每条核对通过就打个勾；有分歧的地方当天在 Issue 里写下结论，不要各自按自己的理解改。

## 一、上架和编辑物品

先核对 `POST /items` 的请求体。前端提交的物品包含名称、归属地点、介绍、是否贵重、启停状态和可借规则这几样，其中名称和归属地点是必填，名称最长五十字，介绍最长三百字。可借规则是一个嵌套对象，里面放单次最长借用天数和可提前预约天数两个数字，这两个值随物品保存，不能在代码里写死。

创建成功时后端要返回 201 和完整的物品对象，至少带上服务端生成的 id 和创建时间，前端拿到 id 之后才能继续传照片、录编号。为了防止手机网络重试造成重复上架，创建请求会带 `Idempotency-Key` 请求头，需要后端确认收到同样的键时不重复建物品。

参数出错时统一返回 400，错误码用 `VALIDATION_ERROR`，并且在 `details` 里按字段名给出原因，前端会把这些原因显示在对应的输入框下面，所以字段名必须和请求体一致。

编辑接口 `PATCH /items/{itemId}` 用的字段和上架完全相同，按部分更新处理。另外要确认一个业务规则：贵重标记的修改只影响之后的新申请，已经提交的预约仍按申请创建时的规则走。

## 二、物品照片

照片走 `POST /items/{itemId}/images`，格式是 `multipart/form-data`，文件字段名叫 `file`。限制条件目前前端按 JPG、PNG、WebP 三种格式、单张不超过 5MB、最多 6 张来实现，**张数上限“6 张”是前端暂定的值，需要和后端确认后写进契约**。

删除照片是 `DELETE /items/{itemId}/images/{imageId}`，成功返回 204。图片本身的访问地址必须受权限控制，存储密钥不能出现在浏览器能拿到的地方。

## 三、实物编号

每条实物的字段是 id、所属物品 id、编号 unitCode 和状态。**状态枚举目前定为可借、维修中、停用、遗失四种（`AVAILABLE / MAINTENANCE / DISABLED / LOST`），要和后端确认够不够用**，比如是否需要单独的“已借出”状态，还是借出状态由预约记录体现。

编号在同一个物品内必须唯一。前端在录入时本地先查一次重，后端也要兜底校验；重复时目前约定返回 400，**也有观点认为应该用 409，这个要统一**。另外，处于未归还或待核验状态的实物不允许改状态，服务端要拒绝并返回 `409 INVALID_STATE`。

## 四、库存摘要（容易分歧，重点对）

库存列表页每行要显示“可借几件 / 共几件”。当前约定是后端在 `GET /items` 的每个物品里直接返回 `unitSummary`，里面有 total 和 available 两个数，前端不自己算。**这里有两个点必须确认：一是这个摘要确实由后端来算；二是“可借”的口径——是只统计状态为 AVAILABLE 的实物数，还是再减去该时段已经被确认预约占用的数量。**

## 五、归还核验

核验队列当前约定为复用 `GET /reservations`，用 `status=RETURN_SUBMITTED` 筛选。**也可以单独开一个 `/return-queue` 端点，两种做法取其一，定下来就不要再变。**

队列里每条记录要给前端这些字段：预约 id、物品 id 和名称、实物编号、借用人姓名、提交时间、用户备注、至少一张现场照片。照片对象目前是 id 加文件名，**真实图片地址字段 url 由后端在联调时提供**。

核验提交是 `POST /reservations/{reservationId}/return-verification`，请求体为 decision 加 reason。decision 只有 ACCEPT 和 REJECT 两种；**驳回时必须填原因**，前端在原因为空时会直接禁用驳回按钮，后端也要再校验一次。这个接口同样带 `Idempotency-Key`，管理员重复点击不能产生两个核验结果，已处理过的申请再次提交要返回 404 或 409。

核验通过后，对应实物要在同一个事务里恢复为可借；驳回则保持占用，等用户重新提交归还。还有权限边界：管理员只能核验自己负责的地点或物品下的归还申请，越权返回 403。

## 六、通用约定

错误响应统一是 code、message、details、requestId 四个字段，响应头里同时带 `X-Request-Id`。时间一律用 ISO 8601，服务端存 UTC，界面按上海时区显示。所有字段用 camelCase。列表接口统一支持 page 和 size 参数，核验队列是否需要分页可以顺带确认。
