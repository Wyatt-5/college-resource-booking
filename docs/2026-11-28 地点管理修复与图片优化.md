# 地点管理修复与图片优化

办公室、物资室改为地点管理中的两个独立页签，每类都有新增入口；可预约地点仍单独管理。移除存放地点只需在浮窗中确认一次，不再逐字输入带空格的名称后再次调用浏览器确认。后端继续检查地点内物品和未完成预约/借还，不能绕过占用保护。

云端排查时办公室C没有未移除物品，也没有关联预约；名称实际包含空格。原界面的逐字匹配和二次确认是本次移除交互修正的对象，不能把该情况描述成有库存占用。原物资室为INACTIVE，原数据库全表唯一约束仍占用其名称，是重命名冲突的原因。

新增V17迁移：移除全表名称唯一约束，改为仅ACTIVE地点的去空格边界名称唯一。移除后可创建同名新地点，也可把其他开放地点改为该名称；历史地点保留原ID和名称。新增同名地点不会复活旧地点或继承旧授权、图片。开放地点之间仍不允许重名。新增接口为 `POST /api/v1/locations`，需管理权限、有效会话与CSRF令牌，接口契约已更新。后续迁移从V18开始。

物品、存放地点和可预约地点的列表封面请求 `thumbnail=true`，返回最长边480px的JPEG展示图。原图不改写，详情仍可读取原图。缩略图使用降采样解码，内存缓存限制为64项/8MiB。图片响应带内容ETag和私有缓存重新验证指令，未变更时可返回304；图片更新后ETag改变，读取前仍执行权限检查。列表采用懒加载和异步解码，不将归还凭证图片转换成展示图。

验证：独立PostgreSQL17库的后端73项测试全部通过、零跳过，含空地点移除、同名重建/重命名、开放地点重复拒绝、占用保护、原图保留、缩略图边界、条件请求304及原权限用例；前端23项测试与生产构建通过。1440/390宽度的隔离浏览器14项交互检查通过，含办公室C移除、两类新增和分组显示。浏览器隔离数据不写入云端用户地点。

发布需先备份数据库及图片，再同时更新Java后端与两个网页入口。新后端启动时执行V17；保留旧镜像及备份，检查Flyway、HTTPS登录、创建/移除、缩略图和304响应后确认切换。云端用户地点不由发布脚本自动移除或重命名，管理员更新后自行操作。
