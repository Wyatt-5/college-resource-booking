## 一、改了什么

### 1. 主导航（`styles.css` + `App.vue`）

| 问题 | 处理 |
| --- | --- |
| 390px 下"登录"标签溢出右边界，导航条下方露出灰色横向滚动条 | 导航改为可横滑并隐藏原生滚动条（`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`），加 `-webkit-overflow-scrolling:touch`、`overscroll-behavior-x:contain`、`scroll-snap-type:x proximity`；`.nav-button` 提到 `min-height:44px`、`scroll-snap-align:start` |
| 切换到靠右的栏目时看不到当前所在页 | `App.vue` 增加 `navRef` 与 `keepActiveNavVisible()`，`watch([activeSection, mode])` 后 `nextTick` 把 `.nav-button.active` 滚进可视区（左右各留 14px 边距） |

### 2. 物品卡片 / 地点卡片

- 物品卡：`.item-title-row h3{min-width:0}` + `.item-title-row .status-badge{flex:0 0 auto;white-space:nowrap}`，"贵重"标签不再被长标题挤成竖排两字；`.item-body` 内距收紧、`.item-footer` 允许换行、`.card-book-button` 提到 `min-height:44px`。
- 筛选条：搜索框独占一行；地点下拉 `flex:1 1 140px; min-width:0` 与"只看有库存"并排同一行。
- 地点卡：`.location-overview-card` 取消固定最小高度、图标 44×44、名称 `16px`、箭头 `flex:0 0 auto`，概要三组数字在 390px 内一行排下。

### 3. 预约弹窗（`BookingModal.vue`）

≤600px 改为**整屏面板**：`width:100%`、`height:100dvh`、`margin:0`、`border-radius:0`、`inset:0`，头部 `padding: calc(12px + env(safe-area-inset-top)) 16px 12px`，底部 `env(safe-area-inset-bottom)`；关闭按钮 `min-height:40px`；标题 `18px` 且 `overflow-wrap:anywhere`（长物品名两行不挤掉关闭按钮）；弹窗加 `overscroll-behavior:contain`，背后页面不会跟着滚。

### 4. 时间表

- 物品预约（`ReservationForm.vue`）：`.item-timetable` 在手机上 `max-height:none; overflow:visible`，**去掉弹窗内原来的第二层滚动条**；时段格改为单列（时间 / 状态 / 备注自上而下），`min-height:64px`，字号 12/11/10；日期区 `grid-template-columns:58px repeat(2,minmax(0,1fr))`，前后翻日期按钮 `min-height:46px`、`min-width:44px`；`input[type=date]` 用 16px 防 iOS 聚焦放大；提交按钮整行。
- 地点预约（`RoomPrototype.vue`）：`.space-calendar` 由 `repeat(8,72px) + 横向滚动`（屏上只能看到 4 天）改为 `repeat(4,minmax(0,1fr))` 两行四列，8 天全部可见、不需要横滑；时段格单列排布，`select` 16px，提交按钮整行。

### 5. 我的预约（`MyReservations.vue`）

- 卡片结构改为"正文区 + 操作区"两段：`.reservation-entry-main` 内标题与状态徽标同行分层（`h3` 左、徽标右，徽标 `flex:0 0 auto`），下面是时间行与"数量/用途"摘要行。
- "查看详情"与"取消预约"统一成按钮样式（`.refresh-button` / `.cancel-button`），`min-height:44px`，≤560px 时各自占满整行——原来用 `link-button` 的"取消预约"只有 48×17，手机上点不中。
- 状态颜色按状态分档：新增 `badgeClass()`（已确认 / 待审核 / 已拒绝 / 已取消·已过期），并在 `styles.css` 补 `.badge-reject`。
- 详情弹窗 `dl` 在 ≤560px 变单列（原来是 `110px 1fr`，"归还要求"一类标签被压成竖排）。

### 6. `#90`、`#130` 这类编号清理

前端 `src` 下直接展示内部自增 id 的位置共 7 处，全部改掉：

| 文件 | 原样 | 改为 |
| --- | --- | --- |
| `features/user/ReservationForm.vue` | `预约 #${reservation.id} 已确认` / `申请 #${id} 已提交` | `预约已确认，可在"我的预约"查看时段与状态` / `预约申请已提交，等待其他审核员处理…` |
| `features/rooms/RoomPrototype.vue` | `地点预约申请已提交…（#${result.id}）` | 同上句式，去掉 id（`createReservation` 返回值不再使用） |

### 7. 顺带补的两处

- `styles.css` 原来没有 `.notice` 定义（各页却在使用），补了统一样式；新增 `html{-webkit-text-size-adjust:100%}`。
- `body` 原来的 `min-width:320px` 去掉：视口正好 320px 且带 15px 竖向滚动条时，它会撑出页面级横向滚动条（实测 `documentElement.scrollWidth` 320 > `clientWidth` 305）。

## 二、怎么验的

分两轮。

**第一轮（改前/改后对照）**：本机命令行网络受限时，把真实 `styles.css` 与四个组件的 `<style scoped>` 拼成 DOM 结构与 Vue 模板一致的静态预览页，用 CDP `Emulation.setDeviceMetricsOverride` 设 390×844、320×640、1280×900，脚本量三类指标：横向溢出、可点元素 < 40px、`overflow:hidden` 截断与嵌套滚动容器。改前 → 改后的对照：

| 视口 | 改前 | 改后 |
| --- | --- | --- |
| 390 | 横向溢出：`button.nav-button@417`（"登录"被切、导航条下露出滚动条） | 无页面级溢出，`docScrollWidth == clientWidth`；仅导航内部横滑 |
| 390 | 点击区 < 40px 共 7 类：`logout-button 50×27`、`mode-tab 69×33`、`link-button 87×17 / 48×17`、checkbox `13×13`、`card-book-button 84×38`、`refresh-button 30×45` | 只剩 checkbox 本体（label 容器 44px 高可点） |
| 390 | 物品弹窗内双层滚动（弹窗 `overflow:auto` + `.item-timetable max-height:330px`） | 单层滚动 |
| 390 | 地点日期条 `repeat(8,72px)+横滑`，屏上只见 4 天 | 两行四列，8 天全可见 |
| 320 | `body{min-width:320px}` 导致页面级横向滚动条 | 无横向溢出（`scrollWidth == clientWidth == 305`） |
| 1280 | — | 桌面布局与改前一致（导航仍竖排、卡片仍网格） |

**第二轮（真实 Vite 渲染，最终结论以此为准）**：`npm install` + `npm run dev`（Vite 8.3.5，`http://127.0.0.1:5173`），后端 8080 未启动，用 CDP `Page.addScriptToEvaluateOnNewDocument` 在页面加载前替换 `window.fetch`，按 `/api/v1/locations`、`/items`、`/items/:id/availability`、`/spaces`、`/spaces/:id/slots`、`/me/reservations`、`/auth/login` 的真实响应结构喂夹具，再用 Vue 编译后的页面逐页操作测量：

| 检查项 | 真实渲染结果 |

| 390 物品预约 | 搜索框独占一行，地点下拉与"只看有库存"同行；"贵重"标签横排；标题两行；可借数量与"预约物品"（44px）同行 |

## 四、没做 / 风险

- **未做真机验收**：iOS Safari 的 `100dvh`、安全区 `env()`、下拉刷新与软键盘遮挡需要手机实测；建议至少在一台 iPhone（Safari）和一台 Android（Chrome）上把五个模块点一遍。
- **后端未参与验证**：本机没有 Docker/PostgreSQL，`~/.m2` 也没有后端依赖，8080 起不来；页面数据是浏览器侧注入的夹具。真实接口的字段与数量级（比如一页 20 条预约、长物品名）可能不同，建议后端起来后再点一遍。
- `keepActiveNavVisible()` 只在 `activeSection`/`mode` 变化时触发；横竖屏切换后如果导航重新溢出，需要用户自己滑一下（未加 resize 监听，避免额外抖动）。
- 审批队列的"申请人"目前只能显示账号（`applicantId`），接口补姓名后再改文案，代码里已留注释。
