# 开发约束：大家按这份规则协作

更新于 2026-11-01。本文件只写**持续有效的协作规则**；本周谁做什么看[本周分工](2026-11-02至11-08任务分工.md)，已经做成什么看[开发日志](开发日志.md)。旧排期和旧接口草案不再作为开发依据。

## 项目要做成什么

- 学院内部使用的共用物品与地点预约系统。手机和电脑访问同一个响应式网站；网站有用户端与管理端。
- 物品归属办公室或物资室，每件实物有编号；可预约地点目前是会议室，后续可添加。人数、地点数、负责人名单不能写死在代码里。
- 最终要跑通登录、上架、预约、需要时审核、领取、拍照备注归还、管理员核验和日志。公告、用户反馈及冲突人工裁决列在[本周分工](2026-11-02至11-08任务分工.md)。**列为目标不等于已经实现。**
- 课程还要求多个子系统在不同机器运行。当前 `worker/` 只有独立进程骨架，跨机器任务调用还没完成；演示前要真实验证，不能用单机启动冒充。

## 文件和接口怎么认

- `frontend/` 是 Vue 用户端与管理端；`backend/` 是 Java API；`worker/` 是未来独立任务服务；`infra/` 管本地数据库；`contracts/openapi/openapi.yaml` 是前后端共同维护的接口契约。
- **判断接口现在能否调用，以当前后端 Controller、数据库迁移和实际测试为准。** OpenAPI 里可能还保留未完成的规划接口，不可只看到路径就说功能交付。当前资源和预约入口见[资源模型与物品接口说明](资源模型与物品接口说明.md)。
- 新增或改动接口时，同一个 PR 更新代码、OpenAPI、必要的数据库迁移与测试。前端集中在 `frontend/src/lib/api.js` 调接口，不在各页面写同学电脑的 IP、端口或数据库密码。
- 已执行过的 Flyway 迁移不回头改，新增表或字段创建下一个迁移文件。照片、账号密码、`.env`、`node_modules`、`target`、`dist` 和真实学生资料不提交 GitHub。
- 图片上传要在后端检查格式、大小和权限。写操作在后端验身份、资源范围及状态；页面隐藏按钮不能代替权限检查。所有审批与资源变更要能追溯到操作者。

## 预约的基本规则

- 普通物品在时段和库存允许时直接确认；贵重物品和可预约地点进入待审核。一份申请只需一名有权审核的人处理，申请人不能审自己的申请。
- 同时提交同一资源时，由后端事务检查容量和时段。物品自动确认按服务端处理顺序；已确认的预约不能被悄悄覆盖。
- **当前地点预约代码仍有“辅导员待审申请硬优先”的限制。** 本周要改成：需要审核的资源允许学生和辅导员都申请，由有权审核者决定给谁，并记录审核人及理由。当前代码与目标的差距不能在演示时说成已完成。
- 物品预约可跨天但时间须整点，并遵守该物品的提前天数和最长借用天数；可预约地点目前只允许未来一周内同一天的 08:00–22:00 整点时段。最终以服务端再次校验为准。
- 领取、拍照归还和核验还没形成真实闭环。归还缺照片不能成功，管理员未核验前不能把实物重新算成可借。这一块由本周负责人实现。

## GitHub 怎么配合

- 一个仓库，`main` 放稳定可演示版本，`develop` 用于日常集成；每个任务从最新集成代码开短分支，做完提 PR，不长期占一条个人分支。
- Issue 写清谁负责、要做成什么、怎么验收。PR 写改了什么、怎样测试、是否有迁移或接口变更。至少请另一位组员看过代码和测试，再合并。
- 同一个文件要多人改时先在群里说清边界；数据库迁移编号、公共导航和 OpenAPI 由组长统筹。合并冲突需要功能负责人参与，不能让组长猜字段含义。
- 每人先在自己电脑运行并测试，周末再按真实账号和数据库验收。开发日志只记录实际完成与证据；未交付的功能写“未完成”。个人贡献看 Issue、本人提交、PR、测试和演示记录，不按代码行数算。

## 上线前还要补的验收

本地可用不等于可以上线。正式给学院使用前，至少验证手机和电脑、不同机器部署、HTTPS、权限隔离、并发预约、照片备份与恢复，以及数据库备份恢复。部署账号与密钥只能放在受保护的配置中。
