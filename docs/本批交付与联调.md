## 审查顺序

1. 本批依赖前端PR #2，先以草稿提交，暂以前端功能分支为比较基准，便于只查看本批增量。
2. 草稿期间不合并到前端功能分支。先由组内完成PR #2的审查和合并。
3. PR #2合并后，将本批PR目标改为develop，核对差异。若前端PR采用压缩合并，需先整理本批分支历史再改目标，避免重复提交。
4. 前后端确认暂定规则，协调V3/V4迁移编号，接入正式身份/授权，完成审查及自动检查后再标记为可合并。

## 请前端确认

- rules使用maxBorrowDays/advanceDays；库存由后端返回unitSummary.total/available。
- 未传page/size兼容原数组，传分页参数返回content/page/size/totalElements；管理列表使用scope=managed。
- 默认图片最多6张、编号重复400、系统占用状态与手工维护状态的边界。
- 表单字段错误、重复点击、上传失败、无权限、空列表等反馈是否符合页面预期。
