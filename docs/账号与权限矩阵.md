# 账号与权限矩阵（第一版）

账号由系统管理员建立，不开放公共注册。人员数量和角色由数据库维护，不把辅导员或学生负责人姓名、人数写进代码。一个账号可以有多个角色。

| 操作 | 普通用户 USER | 辅导员 COUNSELOR_ADMIN | 资源管理员 RESOURCE_MANAGER | 审核员 REVIEWER | 系统管理员 SYSTEM_ADMIN |
|---|---|---|---|---|---|
| 浏览资源、预约本人资源、取件、提交归还 | 是 | 是 | 是 | 是 | 是 |
| 维护物品、核验归还 | 否 | 有管理权限 | 仅授权的地点 | 否 | 可授权及处理异常 |
| 审核贵重物品和会议室 | 否 | 仅同时具有审核员身份时 | 仅同时具有审核员身份时 | 是，但不能审核自己的申请 | 仅同时具有审核员身份时 |
| 会议室优先占用 | 否 | 是，须有理由、通知和审计 | 否 | 否 | 仅同时具有辅导员身份时 |
| 建账号、修改角色与审核组 | 否 | 否 | 否 | 否 | 是，禁止修改自己的授权 |
| 查全量审计日志 | 否 | 由系统管理员另行授权 | 否 | 否 | 是 |

`USER` 是每个启用账号的基础权限。`REVIEWER` 来源于 `reviewer_memberships`，不是靠固定的十人名单。其他角色来自 `role_grants`；资源管理员必须绑定地点。每次受保护操作应查询数据库中的当前账号状态和权限，不能只相信页面隐藏或登录时缓存的角色。

账号停用后不得继续访问受保护接口；账号启停接口安排在第 2 周实现。新建账号密码只保存哈希。登录采用服务端会话；浏览器先取得 CSRF token，再提交登录或其他变更请求。所有授权变更及账号创建写入追加式审计表，审计字段包括操作者、动作、结果、对象、前后数据和时间。

本文件定义通用授权基础；预约冲突、单人审批、禁止自审、辅导员优先等资源规则仍由对应业务模块执行。公共服务可调用 `AuthorizationService.requireReviewerOtherThanApplicant` 检查审核员身份与禁止自审。
