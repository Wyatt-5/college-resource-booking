# 账号与权限：当前能做什么、下周要改什么

核对日期：2026-11-01。账号不开放自行注册；目前系统管理员在管理端实名创建账号并设置初始密码，密码只保存哈希。角色和审核员身份存在数据库里，不按“六位辅导员、十位负责人”的名字写死。

## 当前代码中的权限

| 身份/授权 | 当前可做的事 | 当前限制 |
| --- | --- | --- |
| 普通用户 `USER` | 登录、浏览资源、提交和取消本人的预约 | 不能上架、管理账号或审核 |
| 系统管理员 `SYSTEM_ADMIN` | 建账号、查询账号、改角色授权、管理资源、看审计记录 | 不能修改自己的授权；要审核申请仍须有审核员身份 |
| 辅导员管理员 `COUNSELOR_ADMIN` | 管理资源及可预约地点 | **当前不能建账号或改角色**；这是下周要补的功能 |
| 审核员 `REVIEWER` | 审核贵重物品和地点申请 | 不能审核自己的申请；一份申请一人处理即可 |
| 地点范围管理员 `RESOURCE_MANAGER` | 管理授权地点内的物品 | 这是当前数据库里的技术授权，不是计划给用户另开的一类账号页面 |

同一个账号可以有多个权限。例如辅导员同时加入审核小组后可以审核他人的申请，但仍不能审核自己的申请。后端要检查当前账号、授权范围和预约状态，不能只靠前端隐藏按钮。

## 下周要实现的目标

1. 管理界面只按**普通用户、系统管理员、辅导员管理员、审核员**四类向使用者解释身份；现有 `RESOURCE_MANAGER` 数据和地点范围先核对兼容方式，不能直接删掉导致负责人失权。
2. 系统管理员和辅导员管理员可以按姓名创建内部账号、发放初始密码；普通用户不能自己开户。辅导员可创建哪些身份、能否分配审核员，由负责人先定权限边界，**不能让辅导员给自己或别人授予系统管理员权限**。
3. “账号管理”和“账号与权限”合成一个界面，提供创建、查看、停用和授权；每次开户、停用、授权变更要记录实际操作者。

这些是[本周分工](2026-11-02至11-08任务分工.md)的验收目标，**目前不能把辅导员开户、统一界面和停用账号说成已完成**。接口字段和错误码以代码、OpenAPI 与实际联调为准。
